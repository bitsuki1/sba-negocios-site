## O que é a BANCA (método E-067 · MR-77)
A banca é o mecanismo de **auditoria multi-lente com convergência** que o portfólio usa antes de fechar uma onda de trabalho. Vem do E-067 na colheita Keepee 22/08 (a última grande onda de método antes desta). Estrutura:

1. **Lentes diferentes** — pelo menos 3 passadas com ângulos distintos (ex.: correctness · segurança · propagação · completude · rastreabilidade · falha silenciosa). Cada lente é uma frase-gatilho que a instância dispara sobre o próprio trabalho.
2. **Convergência** — o achado só vale quando 2 ou mais lentes independentes o confirmam. Achado de uma lente só = **hipótese**, não achado; passa mais uma lente antes de virar achado.
3. **Achado-vira-linha** — cada achado confirmado ganha 1 linha no `_NO.md` do nó / no mapa da unidade, com dono + DoD. Zero achados soltos.
4. **Anti-self (D108)** — a instância que produziu o material NÃO é a mesma que audita. Para isso ela **dispara subagentes de contexto fresco** para as lentes (o Task/Agent do Claude Code). É o antídoto contra o "audit theater" (a mesma cabeça declara-se ok).
5. **Triplo-limpo (D82)** — a banca só termina quando 3 rodadas seguidas fecham SEM novos achados críticos. Se a 2ª rodada ainda produz crítico, roda uma 3ª. É o critério de convergência dura.

## Quando rodar
- **ANTES DO FECHO** de uma onda de organização/consolidação (para pedir selo).
- **DEPOIS** de trabalho material significativo (nova diretriz aplicada, nova frente executada, superfície nova criada, refactor de organograma).
- **NÃO** roda banca a cada commit (é onda-a-onda, não commit-a-commit).

## Como rodar (roteiro curto — a instância adapta)
1. **Escolher 3-5 lentes** que casam com o tipo de onda:
   - **Onda de consolidação/organização** (SBA, PU, EDU, Profinders operacional): correctness + propagação + rastreabilidade + completude + falha silenciosa.
   - **Onda de repo-app/site** (sba-site, hub, MR): correctness + segurança + regressão + acessibilidade + UX.
   - **Onda de negócio** (não trava selo — mas vale banca opcional): fiscal/legal + risco + numeros + comunicação.
2. **Disparar 1 subagente por lente** (contexto fresco; anti-self D108). Cada subagente recebe: a lente + o alvo material + a régua *"achado só vira-linha se outra lente confirmar."*
3. **Consolidar convergências** — o que 2+ lentes disseram vira achado; o resto fica como *hipótese_da_lente_X* na pasta `banca/hipoteses/`.
4. **Achado-vira-linha** — cada achado confirmado ganha 1 linha no mapa/`_NO.md` correspondente, com dono e DoD.
5. **Repetir até 3 rodadas SEM crítico novo** (triplo-limpo). Aí a onda está pronta para fechar.
